# Layla Talking Story Mini-App

iPhone/iPadのLayla有料版で、キャラクターと会話しながら物語を進める個人用ローカルLLM Mini-Appです。配布・販売予定はありません。

## 主な機能
- 物語の本文（正本）と、ユーザーの行動・台詞入力
- **生成候補は既定で確認後に採用**。候補編集・再生成・停止・破棄確認・直前の採用取消に対応
- 自動採用も設定で切替可能
- 人物、世界観、あらすじ、ゴール、禁止事項、**章に依存しない自由記憶**
- 通常の日本語文章と `[海:名称≡<虎田海>]` のようなキャラブック記法を混在可能
- モデルの入力コンテキスト長設定、各項目の省略量と概算トークン数の表示
- 直近確定本文（初期設定3600字）を正本とし、過去の生成返答の重複送信を避ける
- Layla SQLiteを主とする世代保存（直前世代保持）とIndexedDB退避
- 退避データとSQLiteが異なる場合は**勝手に上書きせず復旧元を選択**
- 破壊的な操作前の復元点と「直前の状態を復元」ボタン
- 下書き・未採用候補を状態に含めて自動保存。アプリ非表示時にも保存を開始
- 全設定・記憶・本文・履歴のJSONバックアップ、本文のみTXT/Markdownの入出力
- 緊急救済用のJSONテキストコピー欄、生の保存データ書き出し
- 添付の緑の時計アイコン

## 過去メッセージの編集・ストーリー分岐
- メイン画面の「会話履歴を編集・再生成・巻き戻す」を開きます。最新30件を表示し、前後ページ・番号移動で任意の過去ターンへ移動できます。
- **自分の入力を編集**: 送信済みの入力を修正し、その場で返信を再生成するか、入力欄に戻して調整できます。
- **返信を編集**: 過去のLLM返信全文を編集し、選択したターンまでの新しい展開を確定します。
- **返信を再生成**: そのターンより後の旧展開は別分岐に残し、同じユーザー入力からLLMに新しい返信を作らせます。
- **ここまで戻す**: 指定したターンの終了時点に戻ります。「第1ターンの前に戻す」もあります。
- **直前のターンを分岐して取り消す**: 最新の1ターンの前へ戻り、元の展開を保持します。
- 「ストーリー分岐」から元の本文と履歴を開き直せます。分岐ごとにキャラ設定・自由記憶・下書きなども保存されます。
- 分岐は最大30件まで自動保存します。明示的な「削除」をするまでアプリは勝手に旧分岐を捨てません。本文全体を保持するので分岐が増えるほど端末の保存容量を使用します。

**重要**: 本文を直接編集した結果、過去ターンの文字位置と履歴が一致しなくなった場合は、誤った巻き戻しを防ぐため過去メッセージ操作を停止します。事前にJSONバックアップを取ってください。TXT/MDは現在の分岐の本文のみ、JSONはすべての分岐を含みます。

## 使い方
1. Layla本体で端末内のGGUFを選択します。Mini-App自体はGGUFを読み込まず、モデル切替も行いません。
2. GitHub Actions「Build Layla Talking Story Mini-App」の成功した実行から Artifacts > layla-talking-story-mini-app を取得します。
3. ZIP直下には `index.html`・`app.json`・`icon.jpg` が入っています。Laylaへインポートします。
4. 「設定」に人物・世界観・自由記憶を記載します。
5. ユーザーの台詞・行動を入力して「続きを生成」、候補を確認／編集して「採用」を押します。
6. 定期的にJSONをiOS「ファイル」などのMini-App外に保存してください。特に更新・再インポート前に開いて確認してください。

## 重要な注意事項
- 生成品質・モデルの実効トークン数・詳細サンプラーの反映はGGUF/ホストによって変わります。「検索範囲」「傾斜」などのSDK反映は実機未確認です。
- コンテキスト表示は文字数からの**概算**です。長い記憶は一部が省略され、画面で警告します。最新の記憶が自動的に永久保持されるわけではありません。
- 自動保存は端末・OSによる突然のアプリ終了で完了しない場合があります。外部JSONバックアップを定期的に取ってください。
- 古いJSON（schema=`layla-talking-story-backup`, version=1）とSQLiteの旧 `ACTIVE` 形式を読み込める設計です。
- 旧版の長文設定・超上限本文は**切り捨てずに読み込み**ます。入力欄には新規入力の上限があります。
- 長い本文は画面上の表示を末尾2万字に限定します。全文は設定欄で編集でき、TXT/MDへ出力できます。
- 生成が途中で止まった場合も、勝手に採用しません。
- SQLiteとIndexedDBで編集が衝突した際は、復旧元を手動選択するまで保存を停止します。慎重にJSONバックアップを取ってください。
- Layla実機での生成・停止・SQLite持続性・ファイル共有の最終動作確認は別途必要です。

## 2026-11-24 再レビュー対応
- **復旧元選択**: SQLite／IndexedDBのタイトル・文字数・ターン数・日時を確認し、失敗時は再試行できます。復旧後の設定欄も再描画します。
- **復元点**: 40,000文字以下に分割保存。旧単一行の復元点も読み込めます。復元点を一覧から選択でき、分岐名変更・切替では安全スナップショット枠を消費しません。
- **保存効率**: SQLite内のアーカイブ済み分岐を個別のチャンクへ保存し、変更していなければ再利用します。ルートのJSONバックアップは従来のv1形式を維持します。
- **軽量JSON**: 分岐の本文に共通する接頭部分を共有したv2形式を追加しました。新バージョンはv1/v2を両方読み込めます。古いMini-Appでの復元が必要なら通常の「全データJSON」を使用してください。
- **文脈**: 直近の人間の入力を重複したAI本文なしで補足します。設定は余った予算を再配分し、本文はcontextCharsの範囲内にします。推定トークン量はモデルごとに差があります。
- **取り消し**: 分岐30件の上限でも、別途復元点を作って直前ターンを取り消せます（分岐は増やしません）。
- **本文直接編集**: 単一ターン内の簡単な手直しは履歴の位置を補正します。複数ターンにまたがる改稿後は、本文を維持して履歴だけ再設定する操作が選べます。
- **生成停止**: 0文字で止めた場合は空候補を残しません。停止直後は短時間の再生成ガードを設けていますが、ネイティブの停止完了は実機要確認です。
- **書き出し**: Laylaネイティブ、Web Share、ブラウザのダウンロード、テキストコピーを使い分けます。OSへの保存完了は利用者が確認してください。

### 保存容量に関する注意
30分岐を無制限に増やす用途では、アプリ内JSON（通常v1）や復元点が大容量になる場合があります。SQLiteのアーカイブ分離は書込量を抑えますが、端末全体の容量がゼロになるわけではありません。定期的に軽量JSONおよび外部バックアップを確認し、不要な分岐を整理してください。

## 開発
Node.js 22。 `npm install` → `npm test` → `npm run build` → `npm run verify`。

GitHub Actionsは依存導入・単体テスト・ZIPビルド・パッケージ検証・ソースレビューTXT作成を実施します。

ソースレビューTXTは `public/app.json`・アイコン画像・自動生成物を除く、レビュー向けのテキスト結合です。
